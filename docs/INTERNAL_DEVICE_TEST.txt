위굴: 본인 휴대폰에서 내부 테스트하는 방법 (2026-09-08)

추천: Google Play 내부 테스트 트랙에 본인 계정만 등록한다.
이 트랙의 앱은 등록하고 참여한 테스터에게 배포하며, GA 일반 공개는 별도다.
친구나 외부 테스터를 먼저 모집할 필요는 없다.

준비 순서
1. 검토한 BE API와 DB V25를 먼저 배포하고 정상 상태를 확인한다.
   기본 OFF로 배포한 뒤 본인 위굴 계정 UUID만 허용해 활성화한다.
   PURCHASE_COMPARISON_ENABLED=true
   PURCHASE_COMPARISON_ALLOWED_USER_IDS=<본인 위굴 UUID>
   Play 테스터 이메일과 위굴 UUID는 서로 다른 설정이다.
   테스트 트랙이 BE 서버/DB까지 분리해 주지는 않는다.
   별도 테스트 계정을 사용하고 테스트 상품/금액을 기록한다.
2. FE에 접속 가능한 HTTPS API 주소, Firebase 설정, 업로드 서명을 준비한다.
   com.sa0sa.wigul 패키지는 유지한다.
   .env, google-services.json, key.properties, keystore와 비밀번호는 Git에 올리지 않는다.
3. Play Console에서 기존 트랙들의 최대 versionCode를 확인하고 그보다 높은 새 번호를 지정한다.
   현재 pubspec.yaml의 1.0.0+3은 실제 배포 최신 버전이라는 증거가 아니다.
4. Flutter 3.35.7 / Dart 3.9.2 및 Android SDK가 설정된 환경에서 AAB를 빌드한다.
   아래 version-name / unused-higher-code는 확인 후 실제 값으로 바꾼다.

FE 빌드 명령 (FE 저장소에서, 환경과 업로드 키 준비 후)
flutter --version
flutter doctor -v
flutter pub get
dart run build_runner build --delete-conflicting-outputs
flutter test
flutter build appbundle --release --build-name=<version-name> --build-number=<unused-higher-code>
결과: build/app/outputs/bundle/release/app-release.aab
AAB는 휴대폰에서 직접 여는 파일이 아니라 Play Console에 올릴 배포 파일이다.

Play Console에서 본인이 할 일
1. 위굴 선택 > 테스트 및 출시 > 테스트 > 내부 테스트.
2. 테스터 탭 > 이메일 목록 만들기 > 휴대폰 Play 스토어의 Google 계정 주소 추가 > 저장.
3. 내부 테스트 버전 만들기 > 서명된 AAB 업로드 > 변경사항 확인 후 내부 테스트로 게시.
4. 테스터 탭의 참여 링크를 복사한다.
5. 휴대폰에서 등록한 Google 계정으로 링크를 열고 테스트 참여를 누른다.
6. 링크의 Google Play 이동 버튼으로 위굴을 설치/업데이트한다.
7. 앱 버전과 새 기능 진입을 확인한다. 반영이 늦으면 잠시 기다리고 계정/버전 코드를 확인한다.

본인 테스트 시나리오
[ ] 로그인, 기존 상품/예산이 정상 표시됨
[ ] 쇼핑몰에서 공유 > 위굴로 전달, 가격 미입력 상품도 저장됨
[ ] 상품 2개 선택 > 사진/가격/메모 비교, 원문 링크 열림
[ ] 설문 없이 10,000원으로 샀어요 기록 > 지출 +10,000원
[ ] 8,000원으로 수정 > 총 기여 지출은 8,000원 (18,000원이 아님)
[ ] 고민 중으로 복귀 > 이 상품 기여 지출이 0원으로 돌아감
[ ] 메모와 상태를 앱 재시작 후에도 확인 가능
[ ] 네트워크가 늦어도 중복 지출이 없고 실패 시 재시도 가능
[ ] OFF 전환 후 새 기록은 읽을 수 있고 기존 설문으로 잘못 진입하지 않음
[ ] 작은 화면/큰 글씨/뒤로가기/앱 종료 시 화면 오류가 없음
[ ] Firebase 비교·저장 이벤트 수집 확인

대안: 개발자 USB 설치
개발자 옵션/USB 디버깅을 켜고 PC 연결 후 flutter devices / flutter run으로 개발 빌드를 실행할 수 있다.
단, 현재 앱은 출시 앱과 패키지가 같아 debug 서명으로 Play 설치본을 덮어쓸 수 없다.
기존 앱을 임의로 지우기보다 위의 Play 내부 테스트를 권장한다.

이 안내 작성 시 서버 배포, 서명 AAB 생성, Play 게시, 기기 설치는 실행하지 않았다.
업로드 키가 없으면 Play Console의 앱 서명/업로드 키 관리 화면과 기존 담당자의 보관 위치부터 확인한다.
비밀번호나 키 내용을 채팅으로 붙여넣을 필요는 없다.
