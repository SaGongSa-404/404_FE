# 구매 비교 PR 재검토 — 2026-09-08

대상: BE #265 (00970c7), FE #88 (7ff6408 및 이번 수정).
최신 원격 head/base 및 CI, FE/BE 실제 계약과 호출 흐름을 확인했다.
GitHub에 리뷰 댓글/승인/병합을 제출하지 않았으며 서버 배포도 하지 않았다.

## 발견 후 수정한 사항

1. **P2 — 구매 저장 후 이전 통계 요청이 완료되면 disposed notifier 접근**
   새 화면이 consumptionStatsProvider를 invalidate할 때 기존 비동기 조회가 남아 있으면 `Tried to use ConsumptionStatsNotifier after dispose`가 발생했다. 실제 구매 저장 화면과 지연된 통계 응답을 결합한 테스트로 수정 전 실패를 재현했다. 통계/예산 요청 완료 및 오류 처리에서 mounted를 확인해 종료된 notifier를 갱신하지 않도록 수정했다.
2. **P2 — 기능 OFF 시 새 메모 상품이 기존 설문으로 진입**
   새 CONSIDERING 메모는 별도 outcome을 만들고 BE는 해당 상품의 기존 설문 완료를 409로 거절한다. 기존 FE 카드 클릭은 enabled만 확인해 OFF 계정을 기존 설문으로 보냈다. 이제 hasRecords 계정은 상품 revision을 조회해 새 기록이면 읽기 화면으로 이동하고, 손대지 않은 상품은 기존 경로를 유지한다. availability 로딩 중에도 확인을 기다리며 네트워크 실패를 구형 서버로 간주하지 않는다. 구형 서버의 availability 404만 기존 흐름으로 처리한다.

## 검증 및 판정

- 수정 전 지연 응답 회귀 테스트 실패 확인, 수정 후 전체 FE 11개 테스트 통과.
- 구매 모듈·테스트·통계 provider 엄격 정적 분석 통과. 전체 분석 error 0, 기존 warning 2 및 info는 남아 있다.
- BE의 실제 구매 금액 정정, 본인 소유권, revision/요청 키, 구형 설문 경합, 탈퇴 종속 데이터 삭제, OFF 읽기 계약과 기존 테스트를 대조했다. BE 코드는 이 검토에서 변경하지 않았고 기존 CI 성공 상태를 다시 확인했다.
- 검토 범위 내 남은 코드 병합 차단 사항은 발견하지 못했다. 원격 FE CI는 수정 commit push 후 다시 확인한다.

## 출시 전에 남은 검증

Android 서명 빌드, 기기에서 로그인/공유/뒤로가기, 실제 서버 및 Play 업데이트 설치는 아직 확인하지 않았다. CI 성공을 이 단계의 통과로 간주하지 않는다. 새 기록의 7일 회고/합리성·캐릭터 평가는 기존에 명시한 후속 제품 범위다.
